# AgentScope v0.4.0

AgentScope v0.4.0 is the first adapter release. It ships the Generic JSONL adapter, which lets you turn line-delimited action logs (from any agent or script) into valid AgentScope trace files that can be validated and viewed in the Web UI.

## Highlights

- **Generic JSONL adapter.** `npm run agentscope -- import-jsonl <input.jsonl>` reads a file where each line is a JSON object representing one agent action. It normalizes each line into a `TraceAction` and generates run-level metadata automatically.
- **Full action type coverage.** Supports all 6 action types: `read_file`, `edit_file`, `run_command`, `test_failed`, `test_passed`, `generate_summary`.
- **Sensible defaults.** Missing optional fields get reasonable fallbacks: `duration` defaults to `"0s"`, `risk` to `"low"`, `summary` to the action title.
- **Line-level error reporting.** If a line has invalid JSON or a bad `type` value, the CLI reports the line number before exiting.
- **No-overwrite output.** If two traces are generated in the same second, the second gets a `-2` suffix instead of overwriting the first.

## Try it

```bash
# Import the example JSONL
npm run agentscope -- import-jsonl examples/generic-agent.jsonl

# Validate the output
npm run agentscope -- validate .agentscope/2026-06-06-*.trace.json

# View in the Web UI
npm run dev
# Then import the trace via the Import button or drag-and-drop
```

## JSONL format

Each line is a JSON object. Only `type` is required:

```jsonl
{"type":"read_file","title":"Read config","file":"src/config.ts","risk":"low","summary":"Inspected config for the rate-limit setting.","details":["Found setting on line 42"]}
{"type":"edit_file","title":"Bump rate limit","file":"src/config.ts","risk":"medium","summary":"Changed rate limit from 100 to 200.","diff":"- limit: 100\n+ limit: 200"}
{"type":"run_command","title":"Run tests","command":"npm test","risk":"low","summary":"All tests pass.","output":"42 tests passed"}
```

See [`examples/generic-agent.jsonl`](../../examples/generic-agent.jsonl) for a complete 7-action example, and [`docs/adapters.md`](../../docs/adapters.md) for the full field reference and adapter roadmap.

## Auto-generated run metadata

When you import a JSONL file, the adapter generates a complete run:

- `run id`: `run-jsonl-<timestamp>`
- `agent`: `"Generic JSONL"`
- `branch`: detected from current git branch
- `status`: `failed` if any `test_failed` action exists, otherwise `passed` if any `test_passed`, otherwise `warning`
- `trustScore`: 85 (passed), 60 (warning), 35 (failed)
- `filesChanged`: count of unique files across `edit_file` actions
- `commands`: count of `run_command` / `test_failed` / `test_passed` actions

## Known limitations

- **Agent-specific adapters are still planned.** The Generic JSONL adapter works with any line-delimited log, but framework-specific adapters (Claude Code, Codex, Cursor, Aider) that parse native session exports are not yet implemented.
- **Run metadata is inferred, not precise.** The adapter makes reasonable guesses about status, trust score, and file counts, but these may not match what a native recorder would report.
- **No batch import.** Each `import-jsonl` invocation produces one run. Importing multiple JSONL files to produce one multi-run trace is not yet supported.
- **Timestamp and duration are strings.** No parsing or arithmetic is done on these fields.
