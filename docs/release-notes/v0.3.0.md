# AgentScope v0.3.0

AgentScope v0.3.0 moves from a mock trace viewer prototype to a tool you can actually use: generate traces locally with the CLI recorder, validate them, and import them into the Web UI for visual inspection.

## Highlights

- **CLI recorder.** `npm run agentscope -- record -- npm test` wraps any command and produces a trace file with exit code, stdout, stderr, duration, working directory, and git branch.
- **Trace validation.** `npm run agentscope -- validate <trace-file>` checks required fields, enums, and basic value ranges before you import a trace.
- **GitHub Actions ready.** Record and validate traces in CI. Upload them as workflow artifacts and import into the Web UI.
- **Drag-and-drop import.** Drop a `.trace.json` file anywhere on the Web UI page instead of using the file picker.
- **Published trace schema.** `docs/trace-schema.json` defines the format. `examples/auth-fix.trace.json` is a real example you can import and explore.

## Try it

```bash
# 1. Install
npm install

# 2. Record a trace
npm run agentscope -- record -- npm test

# 3. Validate the output
npm run agentscope -- validate .agentscope/*.trace.json

# 4. Launch the viewer
npm run dev

# 5. Import the .agentscope/*.trace.json file (Import button or drag-and-drop)
```

## GitHub Actions

See [`examples/github-actions/record-trace.yml`](../../examples/github-actions/record-trace.yml) for a complete workflow. It checks out the repo, installs dependencies, records a lint run, validates the output, and uploads the trace as a 30-day artifact.

Full guide: [`docs/github-actions.md`](../../docs/github-actions.md).

## Validation

The Web UI validates imported trace files against a lightweight set of rules:

- Top-level must be a JSON object with a `runs` array
- Each run must have `id`, `title`, `agent`, `status`, `trustScore`, `filesChanged`, `commands`, `actions`
- Each action must have `id`, `type`, `title`, `timestamp`, `duration`, `risk`, `summary`, `details`
- Enums are checked: `status` (passed/failed/warning), `type` (6 action types), `risk` (low/medium/high)
- `details` must be a `string[]`

The CLI `validate` command uses the same lightweight validation approach for CI-friendly trace checks.

## Known limitations

- **CLI recorder tracks shell commands, not agent IDE activity.** The recorder wraps a single command. It does not capture file reads, file edits, or multi-step agent reasoning; that level of detail requires a framework-specific adapter.
- **GitHub Actions uploads artifacts but does not comment on PRs.** The current workflow produces downloadable trace files. Automated PR comments with trace summaries are planned.
- **Trace schema is early and may evolve.** The format includes fields for file reads, code edits, and diffs (matching the mock data), but the CLI recorder only populates the command-level subset. Expect the schema to stabilize over the next few releases.
- **Web UI is desktop-first.** The three-column layout works best at 1280px and above. Mobile/tablet polish is planned.
- **Multi-run workflows are basic.** Trace files can contain multiple runs, but comparison and aggregate reporting are still planned for a future phase.
