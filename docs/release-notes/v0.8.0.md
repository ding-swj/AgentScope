# AgentScope v0.8.0

AgentScope v0.8.0 adds trace quality warnings that go beyond structural validation. It introduces advisory checks that flag suspicious patterns in agent runs.

## Highlights

- **Trace quality warnings.** `validate` and `summarize` now surface three advisory checks:
  - Edits without a verification command (tests or typecheck were not run after code changes)
  - Failed tests with no later passing test (the agent did not recover from a failure)
  - High-risk edits with no evidence notes (a risky change has no explanation of why it was made)
- **Warnings are advisory.** Quality warnings do not make validation fail. A trace with warnings is still structurally valid; the warnings help reviewers prioritize which runs need closer inspection.
- **`validate` prints warnings to stderr.** Successful validation output stays on stdout; warnings appear on stderr so CI can surface them without breaking scripts that parse stdout.
- **`summarize` includes a Warnings section.** PR summary Markdown now includes a `### Trace Quality Warnings` section when warnings are present.
- **CLI test coverage.** 19 tests now cover quality warnings, including zero-warning traces, multi-warning runs, and the `summarize` warnings section.

## Try it

```bash
# Validate a clean trace (no warnings)
npm run agentscope -- validate examples/auth-fix.trace.json

# Generate a PR summary
npm run agentscope -- summarize --input examples/auth-fix.trace.json --dry-run

# Run all CLI tests including quality warning coverage
npm test
```

## Quality warning rules

| Rule | Condition | Warning message |
| --- | --- | --- |
| Edits without verification | `edit_file` actions exist but no `run_command`, `test_failed`, or `test_passed` actions | `Run has N edit(s) but no verification command was run.` |
| Failed tests without recovery | A `test_failed` action exists with no later `test_passed` action | `Run has failed test(s) with no later passing test.` |
| High-risk edits without evidence | A `risk: "high"` `edit_file` action has an empty `details` array | `Run has high-risk edit(s) with no evidence notes.` |

All three rules are per-run; a run that triggers none of them produces no warnings.

## Why this matters

Structural validation (`valid status?`, `required field present?`) catches broken data. Quality warnings catch suspicious behavior: an agent that edits code but never runs tests, or makes a high-risk change without explaining why. These are the kinds of signals that help reviewers decide where to focus attention in an agent-generated PR.

## Known limitations

- **Advisory only.** Warnings do not affect exit codes or prevent trace writing. They are reviewer guidance, not policy enforcement.
- **No cross-run comparison.** Each run is checked independently; patterns across runs in a multi-run trace are not compared.
- **No Web UI.** Quality warnings are only visible in CLI `validate` output and PR `summarize` Markdown. The Web UI does not display them yet.
- **Limited ruleset.** The three rules cover common patterns but are not exhaustive. More rules may be added in future releases.
